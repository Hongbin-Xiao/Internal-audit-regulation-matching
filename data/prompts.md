# 提示词模板与两阶段思维链

## 一、七参数模板

`run_bm25_rag.mjs` 与 `run_llm3.mjs` 中的实现，七个参数固定为角色、背景、领域、待查事项、问题描述、参考条文、执行步骤与输出格式（其中「参考条文」为 RAG 阶段动态注入）。

```
【角色】你是一名内部审计专家，负责对审计问题作出专业判断并给出法规依据。
【背景】被审计单位为广西某高校，适用国家法律、自治区规定与校内制度。
【领域】{按问题所属审计领域填入}
【待查事项】{问题定性短语}
【问题描述】{问题描述，截断至 1200 字}

【检索到的参考条文】（作为主要证据，请优先采用）
1.《法规名称》条文……
2.《法规名称》条文……
（未检索到时填「（未检索到相关条文）」）

【执行步骤】①任务确认；②法规定位（结合参考条文与你掌握的现行法规，选定最贴切的法规）；
③条款查找（给出具体条款编号）；④完整性核对；⑤结论。

【输出格式】先简要说明理由，最后一行按"《法规名称》第X条"给出最终采用的法规依据。
```

领域取值由 `ds` 字段映射：`G1` 预算执行审计、`G2` 经济责任审计、`T1` 财务收支审计、`T2` 资产管理审计。

## 二、两阶段思维链

### 阶段一 隐式思维链（问题语义精简与归类）

把非标准化的长文本问题映射到预设审计领域，并压缩为简洁的问题表征。归类结果与法规体系存在映射关系，用于缩小后续检索范围。

### 阶段二 显式思维链（法规定位与条款匹配）

推理过程限定为 5 个递进步骤，以人工预设规则写入提示词：

| 步骤 | 内容 |
| --- | --- |
| ① 任务确认 | 明确问题表征与所属类别 |
| ② 法规定位 | 在知识库中锁定适用法规文件 |
| ③ 条款查找 | 在锁定法规中匹配具体条款 |
| ④ 完整性核对 | 跨法规排查关联条款以防遗漏 |
| ⑤ 版本追溯 | 核查法规更新时间线与条款历史版本 |

## 三、零样本提示词（对照实验用）

`run_llm3.mjs` 第一阶段，用于不注入条文的基线：

```
你是一名内部审计专家。请针对下面的审计问题，列出最多3部可能适用的法规及其具体条款编号，
按相关性从高到低排列。

【审计问题】{问题定性短语}
【问题描述】{问题描述}

输出要求：每行一条，格式为"《法规名称》第X条"，不要解释，不要编造。
```

## 四、设计要点

- **证据约束**：生成阶段要求模型仅以召回条文为主要证据；召回不足以支撑定性时，须显式声明「依据不足」，不得推测条款编号。这一条把「找不到」与「编造」区分开，是抑制法规幻觉的关键。
- **先文件后条款**：②③ 两级定位，避免越级引用——先确定法规文件，再在文件内找条款。
- **双维核对**：④ 横向查跨法规关联，⑤ 纵向查时间效力，落实「法不溯及既往」。
